# 결정 기록 (은기, 0\~3단계 지도 만들기)

0\~3단계를 만들면서 정한 것을 모았습니다. 단계마다 더 자세한 설명과 예시는 [STEP0](./STEP0.md) · [STEP1](./STEP1.md) · [STEP2](./STEP2.md) · [STEP3](./STEP3.md)에 있습니다. 처음이면 [인수인계 문서](./HANDOFF.md)를 먼저 읽으세요.

## 먼저 알아 둘 세 가지

1. **id는 사람이 안 넣고 엔진이 1, 2, 3… 붙입니다.** 엔진은 켜질 때 데이터 파일을 읽어서 다음 번호를 다시 정하므로, 껐다 켜도 번호가 이어집니다.
2. **id로 찾으면 목차(인덱스)를 쓰고, 다른 열로 찾으면 파일을 처음부터 읽습니다.** 이 둘의 속도 차이를 14단계에서 잽니다.
3. **CLI와 서버 중 데이터를 쓰는 건 하나만 켜고 씁니다.** 둘이 같이 쓰면 id가 겹칠 수 있습니다.

## 읽는 법

- 이 문서가 결정의 **원본 목록**입니다. STEP 문서의 "정한 것" 표는 같은 내용에 설명을 붙인 것이라, 결정을 바꿀 때는 이 문서와 해당 STEP 표를 같이 고칩니다.

- **언제** 칸은 그 결정이 적용되는 상황입니다 (예: "INSERT할 때").
- **출처** 칸이 "DESIGN.md 제안과 같음"이면 [DESIGN.md](../DESIGN.md) 4절의 제안을 그대로 따른 것입니다. "새로 정함"은 DESIGN에 없어서 만들면서 정한 것, "교차 검토로 정함"은 두 검토자(설계 쪽, 구현 쪽)가 코드를 직접 돌려 보고 문제를 찾아 고치면서 정한 것입니다.
- 모두 아직 **팀 합의 전**입니다. 회의에서 합의된 것만 DESIGN.md 4절로 옮깁니다.
- 결정을 바꿀 때는 그 줄을 고치고, 왜 칸에 "(변경: 이전에는 ...)"을 덧붙입니다.

| 2 | SELECT에 다른 열 조건이 있을 때 (`WHERE name = ...`) | 파일을 처음부터 읽으면서 조건에 맞는 줄만 남김 | 과제가 "다른 열은 처음부터 읽기(선형 탐색)"와 속도를 비교하라고 함. 거르지 않으면 틀린 결과가 나옴 | DESIGN.md 제안과 같음 + 교차 검토로 거르기 추가 |
