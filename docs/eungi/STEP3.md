# 3단계: API 서버

## 이 단계에서 한 일

다른 코드가 **HTTP로 SQL을 보내면 실행해서 결과를 돌려주는 서버**를 만들었습니다. 아직 스레드(일하는 흐름)는 하나라서 요청을 하나씩 처리합니다. 여기까지가 "지도"입니다.

```
cli.py ─────┐
            ├──→ engine.execute(sql)       ← 둘이 같은 함수를 부름 (접점 1)
server.py ──┘
   ▲  POST /query {"sql": "..."}           ← 접점 4
curl, 다른 코드
```

서버는 엔진 속을 모릅니다. 요청에서 SQL을 꺼내 `engine.execute`에 넘기고, 결과를 `{"results": [...]}`로 감싸 돌려줄 뿐입니다. 그래서 서버를 붙여도 엔진 코드는 바뀌지 않습니다.

## 헷갈리기 쉬운 것

**Q. CLI와 서버는 뭐가 다른가요?**

| | CLI (`cli.py`) | 서버 (`server.py`) |
| --- | --- | --- |
| 누가 씀 | 사람이 터미널에서 | 다른 코드가 HTTP로 (`curl` 등) |
| 켜져 있는 시간 | SQL 파일 하나 처리하고 끝 | 켜 두면 계속 요청을 기다림 |
| 결과 | 화면에 출력 | JSON으로 돌려줌 |

**Q. 왜 주소가 `/query` 하나뿐인가요?**
SQL 안에 동작(INSERT인지 SELECT인지)이 이미 들어 있어서 주소를 나눌 필요가 없습니다.

**Q. 잘못된 요청을 보내면요?**

| 보낸 것 | 응답 |
| --- | --- |
| 정상 SQL | 200 `{"results": [...]}` |
| 틀린 SQL (예: `SELEC *`) | 200 `{"results": [{"type": "error", ...}]}` (지금은 SQL 오류도 결과 안에 담음) |
| JSON이 아닌 본문, `sql`이 없음, `sql`이 글자가 아님 | 400 `{"error": {"code": "bad_request", "message": ...}}` |
| 없는 주소 (`/nope`) | 404 (지금은 HTML. 17단계에서 JSON으로) |

**Q. ⚠️ 서버를 켜 둔 채로 CLI로 INSERT해도 되나요?**
**안 됩니다.** 서버는 켜질 때 "다음 번호 = 3"을 기억해 둡니다. 그 사이 CLI가 따로 3을 쓰면, 서버는 그걸 모르고 또 3을 붙여서 **id가 겹칩니다.** 16단계 lock은 한 프로그램 안만 막아서 이 경우는 못 막습니다.
→ **데이터를 쓰는 건 둘 중 하나만.** 서버가 켜져 있으면 INSERT는 서버로만 보내고, CLI로 넣었으면 서버를 다시 켜세요. (읽기 SELECT는 괜찮습니다.)

## 이 단계에서 정한 것

| 어디서 | 정한 것 | 왜 (안 하면 생기는 일) | 출처 |
| --- | --- | --- | --- |
| 서버 | 표준 `http.server` 사용. 주소는 `POST /query` 하나 | 설치 없이 만들 수 있음. SQL 자체에 동작이 담겨 있음 | DESIGN.md 제안과 같음 |
| 서버 | 포트는 8000 | macOS는 5000번을 AirPlay가 쓸 수 있음. mini-redis와 같은 포트 | 새로 정함 |
| 서버 | 엔진은 서버가 켜질 때 하나만 만들어 모든 요청이 같이 씀 | 요청마다 엔진을 새로 만들면 매번 파일을 다시 읽고, 다음 번호가 어긋남 | 새로 정함 |
| 서버 응답 | `{"results": engine.execute(sql)}`, 한글은 그대로 | 접점 4. `curl`에서 바로 읽힘 | DESIGN.md 제안과 같음 |
| 서버 응답 | 잘못된 본문은 400 `{"error": {...}}`. 응답 쓰는 부분은 `_send(상태, 내용)` 하나로 | 안 하면 서버가 응답 없이 연결을 끊어 버림(`curl: (52) Empty reply`). `_send`는 17단계에서 404·503에도 씀 | 교차 검토로 정함 |
| 사용 규칙 | 데이터를 쓰는 프로그램은 하나만 (서버가 켜져 있으면 CLI로 INSERT 안 함) | 안 지키면 id가 겹침. lock으로는 못 막음 | 교차 검토로 정함 |

## 완료 확인

서버를 켜는 터미널과 요청을 보내는 터미널을 **따로** 씁니다. 서버는 켜진 채로 기다리므로 같은 터미널에서는 다음 명령을 칠 수 없습니다.

**터미널 1** (서버를 켜 둠)
```bash
cd ~/dev/mini-dbms
python3 server.py
```
```
http://localhost:8000 에서 POST /query 를 기다립니다
```

**터미널 2** (새로 열기)
```bash
cd ~/dev/mini-dbms
curl -X POST http://localhost:8000/query -d '{"sql": "SELECT * FROM users WHERE id = 2;"}'
```
```
{"results": [{"type": "select", "columns": ["id", "name", "age"], "rows": [[2, "민수", 31]], "used_index": true}]}%
```
맨 끝 `%`는 오류가 아닙니다. 응답 끝에 줄바꿈이 없어서 zsh가 붙여 주는 표시입니다.

요청이 올 때마다 **터미널 1**에 기록이 한 줄씩 찍힙니다.
```
127.0.0.1 - - [16/Nov/2026 11:48:32] "POST /query HTTP/1.1" 200 -
```
`127.0.0.1` = 내 컴퓨터에서 보냄, `"POST /query"` = 받은 요청, `200` = 성공.

| 확인 | 이렇게 나오면 완료 |
| --- | --- |
| 위 `curl` | 2단계 CLI 결과와 같은 내용 |
| `curl -X POST http://localhost:8000/query -d "{\"sql\": \"INSERT INTO users (name, age) VALUES ('하늘', 22);\"}"` 뒤 CLI로 `SELECT *` | 서버로 넣은 줄이 CLI에서도 보임 |
| `curl -X POST http://localhost:8000/query -d 'not json'` | 400 `{"error": ...}` |
| `curl -X POST http://localhost:8000/nope -d '{}'` | 404 |

다 봤으면 터미널 1에서 `Ctrl + C`로 서버를 끕니다.

## 나중에 바꿀 곳 (Phase 3: 15~17단계)

| 지금 (임시) | 언제 | 어떻게 바뀌나 | 안 고쳐도 되는 곳 |
| --- | --- | --- | --- |
| lock 없음 | 16단계 (**15단계보다 먼저 해도 됨**) | `engine.execute` 안을 `with self._lock:`으로 감쌈 | 서버 (lock은 엔진 안에) |
| 스레드 하나 (`HTTPServer`) | 15단계 | 미리 만든 스레드 N개 + 요청 줄(`queue.Queue`). 줄이 가득 차면 503 | 엔진 |
| 404·501이 HTML | 17단계 | `_send`로 `{"error": {...}}` JSON | 엔진 |
| 틀린 SQL도 200, 틀린 문장 뒤 문장도 실행 | 9단계 (팀 결정 필요) | API는 첫 오류에서 멈출지, SQL 오류를 400으로 할지 결정 | |
| CLI와 서버가 동시에 쓰면 id가 겹침 | 16단계 전 (팀 결정 필요) | 지금처럼 규칙으로 둘지, CLI가 서버로 보내게 할지 | |

16단계를 먼저 하는 이유: 15단계를 먼저 하면 스레드는 여럿인데 lock이 없는 상태가 생겨 id가 겹칠 수 있습니다. 스레드 하나인 서버에 lock을 먼저 걸어도 아무 문제가 없습니다.

## 막히면

| 이런 일이 생기면 | 이렇게 |
| --- | --- |
| `curl: (7) Failed to connect to localhost port 8000` | 서버가 안 켜져 있음. 터미널 1에서 `python3 server.py`가 켜져 있는지 확인 |
| `curl: (6) Could not resolve host: 터미널` | 명령 뒤 설명(`# 터미널 2`)까지 같이 붙여 넣음. 명령만 붙여 넣기 |
| `Address already in use` | 8000번을 다른 프로그램이 씀. `lsof -i :8000`으로 확인하고 끄기 |
| 서버로 넣은 줄이 CLI에서 안 보임 | 서버와 CLI를 같은 폴더(`mini-dbms`)에서 실행했는지 확인 |
| 같은 id가 두 줄 생김 | 서버가 켜진 채로 CLI로 INSERT한 것. 위 ⚠️ 참고. `data/users.tbl`을 지우고 다시 |
