## 1. 식당 비유로 보는 전체 그림

Phase 3 문서는 결국 "손님이 많이 와도 식당이 멈추지 않게, 그리고 주문이 섞이지 않게" 하는 이야기입니다.

| 식당 | 우리 서버 | 나오는 단계 |
| --- | --- | --- |
| 식당 | 서버 프로그램 (`server.py`) | 3단계 |
| 손님 | 요청을 보내는 쪽 (브라우저, `curl`, 주식 화면 프로그램) = **클라이언트** | |
| 주문서 | 요청. 안에 SQL 한 줄이 적혀 있음 | |
| 문 앞에서 손님을 맞는 직원 1명 | **받는 스레드** | 15단계 |
| 대기석 의자 16개 | **큐**(줄) 16칸 | 15단계 |
| 요리사 4명 | **일하는 스레드**(worker) 4개 | 15단계 |
| 요리사들이 같이 쓰는 금고 하나 (안에 장부가 있음) | **엔진**과 데이터 파일 | |
| 금고 열쇠 하나. 한 사람만 들고 들어갈 수 있음 | **lock** | 16단계 |
| "지금 자리가 없어요, 조금 뒤에 오세요" | **503** 응답 | 15단계 |
| "주문서를 5초 안에 다 안 쓰시면 다음 손님 받을게요" | **timeout**, **408** 응답 | 15·17단계 |
| 무슨 문제든 똑같은 양식의 안내 쪽지로 알려 줌 | 모든 오류를 같은 **JSON** 모양으로 | 17단계 |

- **lock이 없으면**: 요리사 둘이 동시에 장부를 펴서 "다음 주문 번호는 4번"을 같이 읽고, 둘 다 4번을 적습니다. 번호가 겹칩니다 (16단계).
- **Thread Pool이 없으면**: 요리사가 1명뿐이라 한 손님의 주문이 끝나야 다음 손님을 받습니다. 주문을 천천히 쓰는 손님 한 명이 있으면 뒤에 선 모두가 기다립니다 (15단계).

## 2. 컴퓨터와 프로그램

| 말 | 뜻 |
| --- | --- |
| 프로그램 | 컴퓨터가 할 일을 적어 둔 것. `python3 server.py`로 실행하면 그때부터 일을 함 |
| 프로세스 | 실행 중인 프로그램 하나. 서버를 켜면 프로세스 하나, CLI를 켜면 또 다른 프로세스 하나. **서로의 메모리를 볼 수 없음** (그래서 CLI와 서버의 lock은 따로임) |
| 운영체제(OS) | Mac, Windows, Linux처럼 컴퓨터 전체를 관리하는 프로그램. 네트워크 연결을 실제로 만들고 끊는 것도 운영체제가 함 |
| 메모리 | 프로그램이 일하는 동안 값을 잠깐 올려 두는 곳. 프로그램을 끄면 사라짐 |
| 디스크, 파일 | 프로그램을 꺼도 남는 저장 공간. 우리 데이터는 `data/users.tbl` 파일에 남음 |
| CPU | 실제로 계산하는 부품 |
| 바이트(byte) | 데이터 크기의 단위. 영어 한 글자 = 1바이트, 한글 한 글자 = 보통 3바이트. 1KB ≈ 1천 바이트, 1MB ≈ 100만 바이트 |
| ms (밀리초) | 1초의 1000분의 1. `0.7ms`는 0.0007초 |
| 터미널 | 글자로 명령을 치는 창. Mac의 "터미널" 앱 |
| CLI | Command Line Interface. 터미널에서 명령으로 쓰는 프로그램. 우리 `cli.py` |
| 명령 옵션 | 명령 뒤에 붙이는 설정. `python3 server.py --port 8001`의 `--port 8001` |
| 기본값 | 따로 안 정하면 쓰는 값. `--workers`를 안 쓰면 4 |
| 경로 | 파일이 있는 위치. `data/users.tbl`, `/Users/me/dev/mini-dbms` |
| 저장소 맨 위 폴더 | `mini-dbms` 폴더 자체. `data/`, `server.py`가 바로 보이는 곳 |
| 로그 | 프로그램이 "지금 무엇을 했는지" 터미널에 찍는 기록. `[worker-2] ... 200` |
| 확인 스크립트 | 코드가 제대로 동작하는지 자동으로 확인해 주는 작은 프로그램. 우리 `checks/` 폴더. "통과"가 나오면 정상 |
| 부하 테스트 | 요청을 일부러 아주 많이 보내서 서버가 얼마나 버티는지, 얼마나 빨리 답하는지 재는 것. 우리 `bench/load_test.py` |
| 중앙값 | 숫자를 크기 순으로 줄 세웠을 때 한가운데 값. 평균과 달리 아주 큰 값 몇 개에 흔들리지 않음 |
| 엣지 케이스 | 평소에는 잘 안 생기는 끝자락 상황. 예: 아무것도 안 보내는 연결, `Content-Length: -1` |
| 시연 | 발표 때 실제로 돌려서 보여 주는 것 |
| 배포 | 내 컴퓨터가 아닌 인터넷의 서버(예: Render)에 올려서 누구나 쓰게 하는 것 |

## 3. 파이썬 문법

| 말 | 뜻 | 예 |
| --- | --- | --- |
| 함수 | 이름을 붙여 둔 일 묶음. 불러서(호출해서) 씀 | `def execute(self, sql):` |
| 인자 | 함수를 부를 때 넘기는 값 | `execute(sql, stop_on_error=True)`의 `sql`, `stop_on_error` |
| 반환값, 돌려줌 | 함수가 일을 끝내고 내놓는 값. `return` | |
| 시그니처, 함수 머리 | `def` 줄. 함수 이름과 받는 인자 | `def execute(self, sql, stop_on_error=False):` |
| 클래스 | 비슷한 물건을 찍어 내는 틀. 틀로 만든 물건 하나를 **객체**(인스턴스)라고 함 | `Engine`은 틀, `Engine("data")`로 만든 것이 객체 |
| `self` | 클래스 안의 함수에서 "나 자신(이 객체)"을 가리킴 | `self._lock`은 "이 엔진이 가진 lock" |
| `__init__` | 객체를 만들 때 한 번 자동으로 실행되는 준비 함수 | |
| 이어받기 (상속) | 이미 있는 클래스를 바탕으로 새 클래스를 만드는 것. 바꾸고 싶은 함수만 새로 쓰고 나머지는 그대로 씀 | `class PooledHTTPServer(HTTPServer):` |
| 덮어쓰기, 바꿔 끼우기 (오버라이드) | 이어받은 클래스에서 같은 이름의 함수를 다시 써서, 원래 함수 대신 내 함수가 불리게 하는 것 | `process_request`, `send_error`를 덮어씀 |
| `super()` | 덮어쓰기 전의 원래(부모 클래스) 함수를 부름 | `super().server_close()` |
| `import` | 다른 파일이나 파이썬 기본 기능을 가져와 쓰는 것 | `import queue` |
| 표준 라이브러리 | 파이썬을 설치하면 처음부터 들어 있는 기능 모음. 따로 설치할 필요 없음 | `queue`, `threading`, `http.server`, `socket` |
| 모듈 | 파이썬 파일 하나. `server.py`는 `server` 모듈 | |
| `dict` (딕셔너리) | "이름 → 값" 쌍을 모아 둔 것. 사전처럼 이름으로 바로 찾음 | `{"sql": "SELECT ..."}` |
| `list` (리스트) | 값을 순서대로 늘어놓은 것 | `[1, "현지", 25]` |
| `None` | "아무것도 없음"을 뜻하는 특별한 값 | |
| `True` / `False` | 참 / 거짓 | |
| `while True:` | 끝없이 반복. 안에서 `return`이나 `break`를 만나야 멈춤 | `_work`의 반복 |
| `try / except / finally` | `try` 안에서 오류가 나면 `except`로 가서 처리. `finally`는 오류가 나든 안 나든 마지막에 반드시 실행 | |
| `with` | 들어갈 때 준비하고, 나갈 때 반드시 정리하는 문법 | `with self._lock:` |
| 데코레이터 `@` | 함수 위에 붙여서 그 함수를 감싸는(앞뒤에 일을 더하는) 문법. 자세한 설명은 [STEP16 ②](./STEP16.md#핵심-코드) | `@locked` |
| `*args, **kwargs` | "받은 값을 몇 개든, 어떤 이름이든 그대로 받아서 넘긴다"는 표시 | |
| `type(이름, (부모,), {...})` | 클래스를 `class` 문법 없이 그 자리에서 만드는 방법 | STEP15 ①의 `timeout`만 바꾼 `Handler` |
| f-문자열 | 글자 안에 값을 끼워 넣는 문법. `f"worker-{n}"` → `worker-1` | |
| 정규식 | 글자 모양의 규칙을 적는 작은 언어. 임시 파서가 SQL을 읽을 때 씀 | |
| 트레이스백 | 파이썬이 오류가 났을 때 "어느 파일 몇째 줄에서 났는지" 길게 찍어 주는 기록. 개발자에게는 유용하지만 파일 경로 같은 내부 정보가 들어 있음 | |
| 상수 | 한번 정하면 바꾸지 않는 값. 보통 대문자 이름 | `BUSY_RESPONSE`, `MAX_BODY` |

## 4. 스레드와 동시에 하기

| 말 | 뜻 |
| --- | --- |
| 스레드 | 프로그램 안에서 일을 하는 "일꾼" 한 명. 프로그램 하나 안에 스레드가 여러 개 있으면 여러 일을 동시에 진행할 수 있음. **같은 프로그램의 스레드들은 메모리를 같이 씀** (그래서 같은 엔진, 같은 장부를 같이 봄) |
| 동시성 / 병렬 처리 | 여러 일을 한꺼번에 진행하는 것. 우리 문서에서는 "요청 여러 개를 한꺼번에 처리"라는 뜻으로 씀 |
| 받는 스레드 | 연결을 받아서 큐에 넣기만 하는 스레드 1개. `serve_forever`를 돌림 |
| 일하는 스레드, worker | 큐에서 요청을 꺼내 실제로 처리하는 스레드. 우리 서버는 `worker-1` \~ `worker-4` |
| 감시 스레드 | 17단계 엣지 방어에서, 연결마다 5초 마감을 재는 스레드 1개 |
| Thread Pool (스레드 풀) | 스레드를 **미리 정해진 수만큼 만들어 두고** 계속 다시 쓰는 방식. Pool은 "웅덩이, 모아 둔 곳"이라는 뜻. 요청마다 새로 만들지 않음 |
| 큐 (queue) | 줄. **먼저 넣은 것을 먼저 꺼냄**(먼저 온 손님 먼저). 파이썬 `queue.Queue`. `put`으로 넣고 `get`으로 꺼냄 |
| `maxsize`, 상한 | 큐의 최대 칸 수. `Queue(maxsize=16)`은 16칸이 차면 더 못 넣음. `Queue(0)`은 거꾸로 "제한 없음"이라는 뜻이라 조심 |
| `put_nowait` | 큐에 넣되, 꽉 차 있으면 기다리지 않고 바로 `queue.Full` 오류를 냄 |
| `get()` | 큐에서 꺼냄. 비어 있으면 무언가 들어올 때까지 그 줄에서 잠들어 기다림 |
| `ThreadingHTTPServer` | 파이썬 기본 서버. 요청이 올 때마다 스레드를 **새로** 만듦. Pool이 아님 |
| `ThreadPoolExecutor` | 파이썬 기본 Thread Pool. `submit(일)`로 일을 맡김. 안쪽 줄의 길이에 제한이 없음 |
| `submit()` | `ThreadPoolExecutor`에 일을 넣는 함수. 줄이 아무리 길어도 무조건 받아 줌 |
| 세마포어 | "남은 자리 수"를 세는 카운터. 들어올 때 1 빼고, 나갈 때 1 더하고, 0이면 더 못 들어옴. 주차장 입구의 "남은 자리 12" 전광판과 같음 |
| `daemon=True` | "주인 프로그램이 끝나면 같이 끝나는 스레드" 표시. 이게 없으면 스레드가 남아 프로그램이 안 꺼질 수 있음 |
| `start()` | 만든 스레드를 실제로 일하게 시작시킴 |
| `join(timeout=1)` | 그 스레드가 끝날 때까지 최대 1초 기다림 |
| lock (잠금) | "한 번에 한 스레드만 들어갈 수 있는 구역"을 만드는 도구. 화장실 열쇠가 하나뿐인 것과 같음. 파이썬 `threading.Lock()` |
| `acquire()` / `release()` | lock을 잠금 / 풂. 이미 잠겨 있으면 `acquire()`에서 풀릴 때까지 기다림 |
| 끼어들기, 경쟁 상태 (race condition) | 두 스레드가 같은 값을 거의 동시에 읽고 고쳐서 결과가 틀어지는 것. 16단계의 "id가 겹침" |
| 교착 상태 (deadlock) | 서로(또는 자기 자신이) 상대가 lock을 풀기를 기다리느라 영원히 멈추는 것 |
| 읽기·쓰기 lock | 읽기끼리는 동시에 들어가게 하고, 쓰기만 혼자 들어가게 하는 lock. 파이썬 표준 라이브러리에는 없음 |
| GIL | 파이썬이 "한순간에는 스레드 하나만 파이썬 코드를 실행"하게 하는 규칙. 스레드가 여러 개여도 계산은 번갈아 함. 대신 네트워크·파일을 **기다리는 동안**에는 다른 스레드가 일할 수 있음 |
| 스레드를 바꾸는 간격 | 파이썬이 한 스레드에게 약 5ms씩 차례를 주고 다음 스레드로 바꾸는 시간 |
| `threading.Barrier(N)` | N개 스레드가 모두 도착할 때까지 기다렸다가 한꺼번에 출발시키는 출발선 |
| `threading.Event` | 한 스레드가 `set()`으로 깃발을 올리면 다른 스레드가 `is_set()`으로 확인할 수 있는 깃발 |
| `threading.current_thread().name` | 지금 이 줄을 실행하고 있는 스레드의 이름 (`worker-2` 등) |
| 이벤트 루프 | 스레드 **하나**가 여러 연결을 번갈아 돌보는 방식. Redis가 이렇게 함 |

## 5. 네트워크와 서버

| 말 | 뜻 |
| --- | --- |
| 서버 | 요청을 기다렸다가 답하는 프로그램. 우리 `server.py` |
| 클라이언트 | 서버에 요청을 보내는 쪽. `curl`, 브라우저, 확인 스크립트 |
| 연결 (connection), 소켓 | 클라이언트와 서버 사이에 놓인 "전화선" 하나. 양쪽이 이 선으로 글자를 주고받음. 파이썬에서는 `socket` 객체 |
| 주소, 호스트 | 서버가 있는 컴퓨터. `localhost`는 "바로 이 컴퓨터". `0.0.0.0`은 "이 컴퓨터로 오는 모든 길에서 받기" (바깥 컴퓨터의 요청도 받음) |
| 포트 | 한 컴퓨터 안에서 프로그램을 구별하는 번호. 아파트의 호수와 같음. 우리 서버는 기본 8000번. 한 번호는 한 프로그램만 쓸 수 있음 (`Address already in use`) |
| 연결 받기 (accept) | 서버가 새로 걸려 온 전화를 받는 것 |
| 운영체제가 받아 두는 연결 수 (`request_queue_size`) | 서버가 아직 "받기"를 하지 못한 연결을 운영체제가 대신 잡아 두는 대기실 크기. 우리 큐(16칸)와는 다른, 더 앞쪽의 대기실 |
| `serve_forever` | 파이썬 `socketserver`의 함수. "연결이 오면 받아서 `process_request`를 부른다"를 서버가 꺼질 때까지 반복 |
| `process_request` | 연결 하나를 받을 때마다 불리는 함수. 원래는 여기서 끝까지 처리했고, 우리는 큐에 넣기만 하게 바꿈 |
| `finish_request` | 요청을 실제로 처리하는 함수. `Handler`를 만들어 읽기 → 실행 → 응답을 함 |
| `shutdown_request` | 연결을 닫는 함수 |
| Handler | 연결 하나를 맡아 HTTP 요청을 읽고, `do_POST` 같은 함수를 부르고, 응답을 쓰는 클래스 |
| `do_POST` | POST 요청이 오면 불리는 함수. 우리는 이것만 만들었음 |
| timeout (시간 제한) | "이 시간 안에 안 오면 그만 기다린다"는 제한. 우리 서버는 5초 |
| 보내기 쪽 / 받기 쪽 | 연결은 양방향이라 "내가 보내는 길"과 "내가 받는 길"이 따로 있음 |
| `shutdown(SHUT_WR)` | 보내는 길만 닫음. "할 말은 다 했다"는 뜻. 받는 길은 열려 있음 |
| `shutdown(SHUT_RD)` | 받는 길만 닫음. 받기에서 기다리던 스레드가 바로 깨어남. 보내는 길은 열려 있어 답은 보낼 수 있음 |
| RST | 운영체제가 연결을 **강제로** 끊는 신호. 상대가 보낸 것을 다 읽지 않은 채 닫으면 이 신호가 가고, 상대는 이미 도착한 답도 못 읽을 수 있음. 전화를 받다가 수화기를 확 내려놓는 것 |
| `linger_close` | 우리가 만든 함수. 답을 보낸 뒤 보내는 길만 먼저 닫고, 상대가 보내던 나머지를 잠깐 읽어 버린 뒤 닫음. RST를 피함 |
| `curl` | 터미널에서 HTTP 요청을 보내는 프로그램. `curl -X POST localhost:8000/query -d '...'` |
| `-d` (curl) | 보낼 본문 |
| `&` (터미널) | 명령을 뒤에서 돌리고 바로 다음 명령으로 넘어감. 여러 개를 동시에 보낼 때 씀. `wait`은 뒤에서 도는 것이 다 끝날 때까지 기다림 |
| Redis | 데이터를 메모리에 두고 아주 빨리 읽고 쓰는 프로그램. 지난 과제 mini-redis가 이것을 흉내 냄 |
| Flask | 파이썬으로 웹 서버를 쉽게 만드는 도구. mini-redis가 썼음 (설치가 필요해서 이번에는 안 씀) |
| Tomcat | Java로 만든 서버에서 많이 쓰는 웹 서버 프로그램 |
| Render | 서버를 인터넷에 올려 주는 서비스 |

<a id="http"></a>
## 6. HTTP (서버와 주고받는 약속)

HTTP는 클라이언트와 서버가 "요청은 이렇게 쓰고, 답은 이렇게 쓰자"고 정한 약속입니다. 요청과 응답은 모두 그냥 글자입니다.

```
POST /query HTTP/1.1                      ← 요청 줄: 방식, 주소, 버전
Host: localhost:8000                      ← 요청 머리 (헤더): 이름: 값
Content-Length: 34                        ←   본문이 34바이트라는 뜻
                                          ← 빈 줄 = 머리 끝
{"sql": "SELECT * FROM users;"}           ← 본문
```

```
HTTP/1.0 200 OK                           ← 상태 줄: 버전, 응답 번호, 짧은 뜻
Content-Type: application/json            ← 응답 머리
X-Worker: worker-2                        ←   어느 스레드가 처리했는지 (우리가 붙인 머리)
                                          ← 빈 줄
{"results": [...]}                        ← 본문
```

| 말 | 뜻 |
| --- | --- |
| 요청 / 응답 | 클라이언트가 보내는 것 / 서버가 답하는 것 |
| 방식 (메서드) | 요청의 종류. `GET`(가져오기), `POST`(보내기), `PUT` 등. 우리 서버는 `POST`만 받음 |
| 주소 (경로) | `/query`. 우리 서버에 있는 주소는 이것 하나 |
| `POST /query` | "`/query` 주소로 POST 요청을 보낸다" |
| 요청 줄 | 요청의 첫 줄. `POST /query HTTP/1.1` |
| 상태 줄 | 응답의 첫 줄. `HTTP/1.0 503 Service Unavailable` |
| 머리, 헤더 | 요청·응답의 본문 앞에 붙는 `이름: 값` 줄들 |
| 본문 (body) | 머리 뒤의 실제 내용. 우리는 JSON |
| `Content-Length` | "본문이 몇 바이트인지" 적어 보내는 머리. 서버는 이 숫자만큼만 읽음 |
| `Content-Type` | 본문이 무슨 형식인지. `application/json`은 JSON |
| `Connection: close` | "이 답을 보내고 연결을 닫는다" |
| `Transfer-Encoding: chunked` | 본문을 조각으로 나눠 보내는 방식. `Content-Length` 대신 씀. 우리 서버는 받지 않음 |
| HTTP/1.0, HTTP/1.1 | HTTP 약속의 판(버전). 우리 서버는 이 둘만 받음 |
| HTTP/0.9 | 아주 옛날 판. 요청에 버전이 없고 응답에 상태 줄이 없음 |
| JSON | 데이터를 글자로 적는 형식. `{"이름": 값}`, `[값, 값]`. 사람도 읽을 수 있고 프로그램도 쉽게 읽음 |
| `http.server`, `socketserver` | 파이썬 표준 라이브러리 중 서버를 만드는 기능. `HTTPServer`는 `TCPServer`를, `TCPServer`는 `BaseServer`를 이어받음 |
| HTML | 웹 페이지를 적는 형식. 사람이 브라우저로 볼 때는 좋지만 프로그램이 오류를 읽기에는 불편함. 17단계 전에는 일부 오류가 HTML로 나갔음 |

<a id="status"></a>
## 7. 응답 번호 (200, 400, 503 …)

응답 번호(상태 코드)는 응답 첫 줄의 세 자리 숫자입니다. 받는 쪽은 숫자만 보고도 결과를 압니다. 첫 자리가 뜻을 나눕니다: **2로 시작 = 성공, 4로 시작 = 보낸 쪽(클라이언트)의 잘못, 5로 시작 = 서버 쪽 사정.**

| 번호 | 이름 | 우리 서버에서 언제 | 우리 `code` |
| --- | --- | --- | --- |
| 200 | OK | 성공 | (없음) |
| 400 | Bad Request | 요청이 잘못됨 (JSON이 아님, SQL이 틀림 등) | `bad_request`, `bad_sql` |
| 404 | Not Found | 없는 주소 (`/abc`) | `not_found` |
| 405 | Method Not Allowed | 주소는 있는데 그 방식은 안 받음 (`GET /query`) | `method_not_allowed` |
| 408 | Request Timeout | 5초 안에 요청을 다 보내지 않음 | `timeout` |
| 413 | Content Too Large | 너무 큼 (본문 1MB 초과 등) | `too_large` |
| 500 | Internal Server Error | 서버 고장 (디스크 오류 등) | `internal` |
| 503 | Service Unavailable | 지금 너무 바쁨. 조금 뒤 다시 보내면 됨 | `busy` |

파이썬 `http.server`가 스스로 내는 번호 중 우리 목록에 없는 것은 17단계에서 목록 안의 번호로 바꿔 보냅니다.

| 번호 | 뜻 | 우리가 바꿔 보내는 번호 |
| --- | --- | --- |
| 414 | 주소가 너무 김 | 413 |
| 431 | 요청 머리가 너무 큼 | 413 |
| 501 | 모르는 방식 (`do_GET` 함수가 없음) | 405 |
| 505 | 모르는 HTTP 버전 | 400 |

<a id="error"></a>
## 8. 오류와 예외

| 말 | 뜻 |
| --- | --- |
| 예외 (exception) | 파이썬에서 "문제가 생겼다"고 알리는 것. 예외가 나면 그 자리에서 하던 일을 멈추고, `except`가 받아 줄 때까지 바깥으로 올라감 |
| 예외를 낸다 (raise) | 일부러 예외를 만들어 알림. `raise ValueError("...")` |
| 위로 올린다 | 그 자리에서 처리하지 않고 부른 쪽에 넘김 |
| `Exception` | 거의 모든 예외를 묶는 가장 큰 종류. `except Exception`은 "어떤 오류든 받는다" |
| `ValueError` | "값이 잘못됐다"는 예외. 우리 프로젝트에서는 **"SQL이 틀렸다"를 뜻하기로 약속**함 (D47) |
| 하위 예외 | 어떤 예외를 바탕으로 만든 더 좁은 예외. `JSONDecodeError`, `TokenizeError`는 `ValueError`의 하위라서 `except ValueError`가 같이 받음 |
| `queue.Full` / `queue.Empty` | 큐가 꽉 참 / 비어 있음 |
| `OSError` | 운영체제와 관련된 오류. 파일·네트워크 문제 (포트가 이미 쓰임, 폴더가 없음 등) |
| `TimeoutError` | 시간 제한이 지남 |
| `BrokenPipeError`, `ConnectionResetError` | 답을 보내려는데 상대가 이미 연결을 끊음 |
| `RecursionError` | 너무 깊이 중첩된 것을 풀다가 파이썬이 포기함. `[[[[...` 같은 JSON |
| `AttributeError` | 객체에 없는 이름을 쓰려 함 |
| `OverflowError` | 숫자가 너무 커서 처리할 수 없음 |
| 오류 응답 | 실패했을 때 서버가 보내는 답. 우리는 모두 `{"error": {"code": "...", "message": "..."}}` 모양 |
| `code` / `message` | 오류의 짧은 이름(프로그램이 읽음) / 사람이 읽는 설명 |

## 9. Git과 협업

| HANDOFF | 작은 버전(working sample)을 돌려 보는 법과, 각자 이어서 만들 곳을 정리한 문서 (`docs/eungi/HANDOFF.md`) |

<a id="project"></a>
## 10. 우리 프로젝트에서만 쓰는 말

| 말 | 뜻 |
| --- | --- |
| DBMS | 데이터베이스 관리 프로그램. 데이터를 저장하고 SQL로 넣고 찾게 해 줌. 우리는 작은 것을 직접 만드는 중 |
| SQL | 데이터베이스에 "이거 넣어 줘(`INSERT`)", "이거 찾아 줘(`SELECT`)"라고 말하는 언어 |
| 테이블, 행, 열 | 표, 표의 가로줄 하나(데이터 하나), 세로줄 하나(`id`, `name`, `age`) |
| id | 행마다 엔진이 자동으로 붙이는 번호 1, 2, 3… |
| `next_id`, 다음 번호 | 다음 INSERT에 붙일 id. 엔진이 기억하고 있음 |
| 엔진 (`engine.py`) | SQL을 받아 실제로 실행하는 중심 부분. CLI와 서버가 같이 씀 |
| `engine.execute` | 엔진의 유일한 입구 함수. SQL 글자를 받아 결과 목록을 돌려줌 |
| 파서 (`parser.py`) | SQL 글자를 읽어 엔진이 알아듣는 모양(`Insert`, `Select`)으로 바꿔 주는 부분 |
| 토크나이저 | SQL 글자를 단어 단위로 자르는 부분 (Phase 1) |
| 실행기 | 파서가 만든 명령을 실제로 수행하는 부분. 지금은 `engine.py`의 `_run` |
| storage (`storage.py`) | 데이터 파일에 쓰고 읽는 부분 |
| 인덱스 (`index.py`) | 책 뒤의 찾아보기. "id 3은 파일의 몇 바이트째" 를 적어 두어 바로 찾게 함 |
| B+ 트리 | 큰 인덱스를 빠르게 찾게 해 주는 나무 모양 구조. Phase 2가 만듦 |
| 스키마 (`schema.json`) | 테이블에 어떤 열이 있고 각 열이 숫자인지 글자인지 적어 둔 파일 |
| 지도 만들기 (0\~3단계) | 엉성하더라도 처음부터 끝까지 한 번 돌아가게 만든 단계 |
| Phase 1, 2, 3 | 팀이 나눈 작업 묶음. 1 = SQL 처리기(4\~9단계), 2 = B+ 트리(10\~14단계), 3 = 동시 처리와 오류(15\~17단계) |
| 접점 | 파일끼리 주고받는 약속(함수 이름, 넘기는 값, 돌려받는 값). DESIGN 2절 |
| D숫자 (D34 등) | 결정 기록([DECISIONS](./DECISIONS.md))의 번호 |
| 엣지 방어 (`server_guard.py`) | 17단계에서 엣지 케이스를 막는 코드만 따로 모은 파일 |
| `stop_on_error` | `execute`의 인자. `True`면 틀린 SQL을 만나는 즉시 멈춤 (서버), `False`면 계속 (CLI) |
| DESIGN, REQUIREMENTS | 팀 설계 문서 / 과제 요구사항 문서 |
