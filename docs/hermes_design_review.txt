너는 이 팀의 설계를 처음 보는 독립 검토자다.
docs/REQUIREMENTS.md(과제 명세)와 docs/DESIGN.md(코드 작성 전 설계, 파이썬 표준 라이브러리만, http.server 기반)
두 파일만 읽어라. 다른 파일은 읽지 마라. 코드는 아직 없다. 파일을 수정하지 마라.

이 설계에서 아직 잘못된 것을 찾아라.

1. 내부 모순: DESIGN.md의 두 곳이 서로 다르게 말하는 곳
   (2장 접점 표와 4장 결정 표, CLI와 API 동작, 3장 완료 기준과 계약, 오류 코드 표와 층별 책임 표)
2. 정해 놓았지만 파이썬 표준 라이브러리로는 틀리거나 불가능한 결정
   (http.server / socketserver / json / 파일 입출력 / fcntl / perf_counter)
   의심되면 python3로 짧은 실험 코드를 직접 돌려서 확인하고, 돌린 코드와 결과를 같이 적어라.
3. 아직 정하지 않아서, 두 사람이 따로 구현하면 같은 입력에 다른 HTTP 응답이나 CLI 출력이 나올 곳.
   구체적인 입력을 적어라.
4. 아직 테스트하기 어려운 곳

이미 올바르게 정해진 것은 건너뛰어라.
항목마다 (DESIGN.md 위치, 구체적인 시나리오, 고치는 방법)을 적어라.
