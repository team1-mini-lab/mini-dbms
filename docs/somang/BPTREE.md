## 접점 3 (그대로 지킴) + 범위 조회

| 함수 | 받는 것 | 돌려주는 것 |
| --- | --- | --- |
| `insert(key, value)` | id(`int`), 파일 위치(바이트) | 없음. 같은 키면 값을 덮어씀 |
| `search(key)` | id | 파일 위치. 없으면 `None` |
| `range_search(start, end)` | 시작 id, 끝 id | `start <= id <= end`인 `[(id, 파일 위치), ...]`, id 오름차순. `start > end`면 `[]` |

`range_search`는 아직 엔진이 부르지 않는다. `WHERE id BETWEEN`이나 `id > ?`는 파서(현지)와 엔진(은기)이 정할 접점이라, 함수만 먼저 만들어 둠 (DESIGN 20단계 후보).

## 결정 기록

팀 전체 결정 기록 [DECISIONS](../eungi/DECISIONS.md#phase2)에도 같은 번호로 모아 두었습니다.

| 번호 | 결정 | 이유 |
| --- | --- | --- |
| S1 | 값에는 데이터 전체가 아니라 **파일 위치(바이트)**를 담음 | 100만 줄을 메모리에 다시 두지 않음. 파일이 원본이고 트리는 목차 (DESIGN 11단계 제안과 같음) |
| S2 | 노드의 키가 `max_keys`개를 **넘으면** 나눔. 기본 `max_keys=256`(처음에는 32), `BPlusTree(max_keys=3)`처럼 바꿔 실험 | 차수에 따른 높이 차이를 발표 재료로 씀 |
| S3 | 리프를 나눌 때 `mid = 키 수 // 2`. 오른쪽 리프의 **첫 키를 부모로 복사** (리프에도 남음) | 모든 키와 값이 리프에 있어야 리프만 옆으로 훑어 범위 조회가 됨. 예: 10,20,30,40 → [10,20] [30,40], 30이 올라감 |
| S4 | 내부 노드를 나눌 때 **가운데 키를 부모로 옮김** (양쪽에 안 남음) | 내부 노드는 길 안내만 하므로 같은 표지판이 두 번 있을 필요 없음 |
| S5 | 내려갈 때 표지판 키와 **같으면 오른쪽**으로 (`bisect_right`) | S3에서 올린 키는 오른쪽 리프의 첫 키이므로 |
| S6 | 노드마다 `parent`를 둠 | 나눈 뒤 키를 올려 보낼 곳을 바로 앎. 공부한 노드 그림과 같음 |
| S7 | 노드 안에서 위치 찾기는 표준 라이브러리 `bisect`(이진 탐색) | 노드 안 키는 정렬되어 있음. 직접 반복문으로 찾아도 결과는 같음 |

## 성능 비교 (14단계)

`python3 bench/run_bench.py` 결과. 무작위 id 100개(name은 10개)로 한 번 평균. 엔진 `execute` 전체(파싱 포함) 시간.

| 건수 | CLI로 넣기 | 엔진 켜기(B+ 트리 다시 만들기) | 트리 높이 | id로 찾기 (인덱스) | name으로 찾기 (처음부터) | 배 |
|---:|---:|---:|---:|---:|---:|---:|
| 10,000 | 0.2초 | 0.02초 | 4 | 0.013ms | 15.1ms | 1,137배 |
| 100,000 | 1.7초 | 0.23초 | 4 | 0.017ms | 149.7ms | 9,019배 |
| 1,000,000 | 16.8초 | 2.57초 | 5 | 0.017ms | 1524.3ms | 88,563배 |

- id로 찾기는 건수가 100배 늘어도 거의 같다 (트리 높이 4 → 5, 한 줄만 읽음).
- name으로 찾기는 건수에 비례해 늘어난다 (매번 파일 전체를 읽음).
- 측정 환경마다 숫자는 달라지므로, 발표 전에 각자 컴퓨터에서 다시 돌린 값을 씀.

## 알아 둔 한계

- id가 1, 2, 3…처럼 늘어나는 순서로만 들어오면, 나뉜 왼쪽 노드는 다시 채워지지 않아 노드가 절반쯤만 찬다. 그래서 같은 건수에서 무작위 순서보다 높이가 조금 높을 수 있다. 실제 DBMS는 맨 오른쪽 분할을 따로 처리하기도 함 (차별화 후보).
- 삭제는 없음 (과제에 `DELETE` 없음).
- 엔진을 켤 때마다 파일을 읽어 트리를 다시 만든다 (100만 건에 약 2.6초). 인덱스를 파일로 저장하는 것은 DESIGN 24단계 후보.
